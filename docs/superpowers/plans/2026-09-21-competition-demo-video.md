# Pip Finance Competition Demo Video Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a polished 1920x1080 Pip Finance product-demo MP4, approximately 140 seconds long, using only recordings of the current web app and covering scan-to-add, bill splitting, Ask Pip chat mode, live net worth, and the Pip Pro purchase experience.

**Architecture:** Create an isolated HyperFrames project at `videos/pip-finance-demo/`. A small Node/CDP capture harness launches a dedicated Chromium profile against the local Expo web build, seeds only the app's existing synthetic demo fixture, records each real UI flow as a separate clip, and stores a verified capture inventory. HyperFrames then owns the approved storyboard, visual framing, narration, captions, audio mix, transitions, validation, preview, and final render.

**Tech Stack:** Expo web, React Native Web, `expo-sqlite`, Chromium DevTools Protocol, Node.js built-in test runner, FFmpeg/ffprobe, HyperFrames product-launch workflow, HTML/CSS/GSAP compositions.

**Spec:** `docs/superpowers/specs/2026-09-21-competition-demo-video-design.md`

## Global Constraints

- Final format is exactly `1920x1080`, 16:9, H.264 video with AAC audio.
- Target duration is approximately `140s`; the core pitch, four requested product features, and monetization segment must appear before `120s`.
- Record the current web build only; no emulator or native-device footage.
- Every product interaction must come from the real app at `http://localhost:8081`.
- Never recreate, redraw, or approximate a Pip screen in HyperFrames.
- HyperFrames may add only editorial typography, captions, restrained callouts, transitions, music, and narration around captured footage.
- Use only bundled synthetic data and a dedicated Chromium profile; never record real financial data, credentials, or a personal browser profile.
- Do not complete a subscription purchase.
- Do not mention Shipathon, judging criteria, or unselected award categories in narration or on-screen copy.
- Preserve all pre-existing and unrelated worktree changes.
- Do not modify application source solely for video production.

- [ ] **Step 3: Implement the CDP request layer**

Create `scripts/cdp-client.mjs` with this public contract:

```js
export function createCdpClient(transport, { timeoutMs = 10_000 } = {}) {
  let nextId = 1;
  const pending = new Map();

  function settle(message) {
    if (!message.id || !pending.has(message.id)) return;
    const entry = pending.get(message.id);
    pending.delete(message.id);
    clearTimeout(entry.timer);
    if (message.error) entry.reject(new Error(message.error.message));
    else entry.resolve(message.result);
  }

  return {
    send(method, params = {}) {
      const id = nextId++;
      return new Promise((resolve, reject) => {
        const timer = setTimeout(() => {
          pending.delete(id);
          reject(new Error(`${method} timed out after ${timeoutMs}ms`));
        }, timeoutMs);
        pending.set(id, { method, resolve, reject, timer });
        transport.send(JSON.stringify({ id, method, params }));
      });
    },
    receive(message) {
      settle(typeof message === 'string' ? JSON.parse(message) : message);
    },
    disconnect(error = new Error('CDP disconnected')) {
      for (const entry of pending.values()) {
        clearTimeout(entry.timer);
        entry.reject(error);
      }
      pending.clear();
    },
  };
}
```
